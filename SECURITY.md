# Security Policy

If you discover a vulnerability, security-related bug, privacy issue, or behaviour that could put users or their data at risk, please report it immediately to:

[reports@colourswift.com](mailto:reports@colourswift.com)

Please avoid opening a public GitHub issue for vulnerabilities that could be exploited.

## What should I include?

A good report should include, where possible:

- The affected application or service
- The affected version
- A clear description of the issue
- Informative steps to reproduce it
- The security impact you believe it has
- Relevant logs, code snippets and/or screenshots

## What should I avoid sending?

Please do not send unnecessary:

- Passwords
- Private tokens
- Personal data
- Leaked user data

If sensitive material is required to investigate the issue, this can be arranged after the initial report.

## Reports That May Not Receive a Response

Reports may receive no response, where they are clearly spam, low effort, or automated output generated by an LLM.

LLMs must not be used to write or generate security reports. Reports should be written by the human submitting them, as we we should reasonably expect the reporter to understand the issue being described.

Such reports will be judged discreetly and may receive no response.

To prevent abuse, bugs that do not have a security or privacy impact may or may not receive a response. Instead, these should be reported through this repository's issue tracker.

## Reports That Will Be Taken Seriously

A technical report, or even a simple report submitted in good faith, will not be ignored and will receive equal consideration.

## Disclosure

Please allow reasonable time for an issue to be investigated and corrected before publishing technical details that could put users at risk.

Always ensure the problem exists in the current official version or beta before submitting a report.

Legitimate security research and responsible reports are highly appreciated.

Thank you.
